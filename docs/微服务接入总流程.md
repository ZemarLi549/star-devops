# 微服务接入总流程

## 1. 目录约定

根目录统一约定：

```text
docs/
scripts_dir/
cpo-api-gateway/
```

业务服务采用独立目录：

```text
cpo-ai-productivity-service/
```

如果后续扩展到全公司使用，目录和部署建议按“共享身份层 + 组织独立业务层”组织：

```text
auth-all/                      # 统一认证与用户体系
cpo-ai-productivity-service/   # 某组织的人效后端
<org-x>-ai-productivity-es/    # 某组织的人效 ES 空间或集群
```

通用文档归档约定：

- `sop-vdoc/docs/`：放页面操作说明、用户使用手册、常规接入说明、SOP。
- 根目录 `docs/`：放部署细节、内网地址、令牌、密钥、端口、防火墙、微服务真实接入细节等敏感文档。

## 2. 接入步骤

1. 新建服务目录。
2. 补 `requirements.txt` 或对应语言依赖文件。
3. 补 `config/application.example.yaml`。
4. 实现 `/healthz`。
5. 实现最小业务接口。
6. 在 `cpo-api-gateway/krakend.json` 中新增路由。
7. 在前端新增页面或子页面。
8. 在 `scripts_dir/` 中新增启动脚本。
9. 在根目录 `docs/` 中补接入文档。
10. 如需服务器直装，再补 `install-*-binary.sh` 和 `start-*-binary.sh`。

## 3. 当前建议顺序

1. `cpo-api-gateway`
2. `auth-all`
3. `cpo-ai-productivity-service`
4. `cpo-feishu-collector-plugin`
5. AstrBot 适配接口

## 4. 配置原则

- 通用配置走 Nacos。
- 敏感信息只放后端配置或环境变量。
- 前端不持有飞书密钥、上传 token、数据库密码。
- 统一网关当前采用 `KrakenD CE`，优先走声明式路由而不是自研转发程序。
- 登录统一由 `auth-all` 承接，网关只负责透传 `Authorization` 和基础治理。
- 元素级权限、页面权限、数据权限继续由业务系统自己控制。

## 5. 扩展问题记录

AI 人效自动化系统后续推广到全公司时，已经确定以下扩展原则：

- 最终统计结果也进入 ES，不只原始事件进 ES
- 每个组织 / 部门可以独立部署一套后端 + ES
- 全公司统一复用 MySQL 用户表
- 平台维护空间注册信息，切换空间时调用对应空间后端
- 当前默认先使用内置空间
- 共享层只承担身份和组织主数据
- 组织层承担自己的采集、统计、事项、日报、通知等业务数据
- 历史数据清理由空间自己负责，公共平台不跨空间执行删除

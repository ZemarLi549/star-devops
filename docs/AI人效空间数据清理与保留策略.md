# AI人效空间数据清理与保留策略

更新时间：2026-08-11

## 1. 目的

本文用于说明 AI 人效自动化系统在多空间部署后的历史数据清理责任、保留周期、执行方式和安全边界。

适用范围：

- 内置空间
- 组织 / 部门独立空间
- 空间独立后端
- 空间独立 Elasticsearch
- 用户本地飞书采集器缓存

## 2. 清理责任边界

### 2.1 用户本地采集器

用户本机或托管机器上的 `cpo-feishu-collector-plugin` 只负责：

- 本地原始聊天文件
- 本地日报历史文件
- 本地会议 / 文档预留历史目录
- 本地 token 之外的运行日志

用户侧清理脚本：

```bash
cd cpo-feishu-collector-plugin
bash bin/clean-history.sh
```

用户侧清理不会删除服务端 ES 数据。

### 2.2 空间后端

每个空间自己的 `cpo-ai-productivity-service` 负责：

- 本空间事件接收记录
- 本空间 AI 日报 / 周报文件
- 本空间通知记录
- 本空间本地临时数据

空间后端不得清理其他空间的数据目录。

### 2.3 空间 Elasticsearch

每个空间自己负责维护对应 ES：

- 原始聊天事件索引
- 会议 / 文档原始事件索引
- 最终统计索引
- AI 日报 / 周报索引
- AI 事项 / 待办索引
- 通知和运行状态索引

公共平台不直接跨空间执行删除操作。

## 3. 默认保留周期

当前建议默认值：

| 数据类型 | 推荐保留时间 | 说明 |
| --- | ---: | --- |
| 聊天原始事件 | 15 天 | 只用于短期检索和 AI 上游分析 |
| 会议 / 文档原始事件 | 15 天 | 可按组织合规要求缩短 |
| 最终统计结果 | 180 天 | 用于趋势、排行和自由分析 |
| AI 事项抽取结果 | 180 天 | 支撑待办和日报追溯 |
| AI 日报 / 周报 | 180 天 | 默认保留半年 |
| 通知记录 | 180 天 | 用于故障追踪和授权审计 |
| 用户本地运行日志 | 15 天 | 防止本地磁盘持续增长 |

说明：

- 组织可以在自己的空间内缩短或延长周期。
- 延长保留周期需要评估 ES 容量、隐私和合规要求。
- 共享 MySQL 用户主数据不由人效空间清理任务删除。

## 4. ES 清理方式

推荐优先使用 Elasticsearch 生命周期管理能力：

1. 每个空间配置独立 index prefix。
2. 每类数据按日期创建索引。
3. 为每类索引配置对应的生命周期策略。
4. 由空间管理员维护策略和容量。

推荐索引前缀：

- `cpo-productivity-chat-raw-*`
- `cpo-productivity-meeting-raw-*`
- `cpo-productivity-document-raw-*`
- `cpo-productivity-summary-*`
- `cpo-productivity-action-items-*`
- `cpo-productivity-ai-report-*`
- `cpo-productivity-notification-*`

如果暂时未启用 ES 生命周期管理，可以使用空间自己的清理脚本按 `retentionUntil` 或索引日期清理。

## 5. 空间清理脚本要求

每个空间的清理任务应满足：

- 只操作当前空间的 ES 地址和 index prefix
- 支持 `--dry-run`
- 支持按数据类型单独清理
- 支持按天数覆盖默认保留期
- 执行前输出待删除索引和文档数量
- 执行结果写入空间日志
- 删除失败要写入空间通知
- 同一空间同一时间只允许运行一个清理任务

建议命令形式：

```bash
./scripts/cleanup-space-history.sh --space-id builtin --dry-run
./scripts/cleanup-space-history.sh --space-id builtin
./scripts/cleanup-space-history.sh --space-id org-a --raw-days 15 --summary-days 180
```

当前这些命令属于空间运维脚本规范，后续脚本统一放到根目录 `scripts_dir/`。

## 6. 清理执行频率

推荐：

- 每天凌晨执行一次 ES 生命周期检查
- 每天凌晨执行一次空间本地文件清理
- 每周执行一次容量和失败任务检查
- 每月审计一次保留策略

不建议在业务高峰期执行大批量 force merge 或大范围删除。

## 7. 空间切换与清理关系

用户切换空间时：

- 查询只访问当前空间后端
- 统计只读取当前空间 ES
- 日报只读取当前空间数据
- 事项只读取当前空间事项索引
- 通知只读取当前空间通知索引

清理任务也必须携带 `spaceId`，避免误删其他空间数据。

## 8. 共享 MySQL 用户表边界

共享 MySQL 用户表只用于：

- 平台账号
- 员工号
- 组织 / 部门关系
- 飞书 `open_id`
- 三方工作台 ID
- LDAP / 本地登录映射

空间清理任务不得删除共享用户主数据。

如果用户离职或被删除：

- 先由身份系统处理用户状态
- 再按组织合规策略处理该用户在对应空间的业务数据
- 处理过程必须留审计记录

## 9. 安全要求

- ES 凭证只保存在空间后端或空间运维环境中
- 前端不允许直接调用 ES 删除接口
- 公共管理员默认不能跨空间删除数据
- 高风险删除必须支持审批或二次确认
- 清理日志不能记录 App Secret、API Key、用户 token
- 生产清理前必须先执行 dry-run

## 10. 当前默认空间

当前默认使用 `builtin` 内置空间。

内置空间也必须按独立空间执行：

- 独立后端配置
- 独立 ES 地址或 index prefix
- 独立清理策略
- 独立清理日志
- 独立失败通知

后续新增组织空间时，复制这套空间级清理约束，不复用跨空间删除脚本。

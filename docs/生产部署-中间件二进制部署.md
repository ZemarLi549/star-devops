# 生产部署-中间件二进制部署

更新时间：2026-08-18

## 1. 文档目标

本文用于规范 `star-devops` 当前依赖的中间件生产部署方式，原则上优先采用：

- 官方二进制包
- 官方 `tar.gz` / generic binary
- 本机服务化部署

不推荐把生产环境长期建立在开发态 `docker run` 或临时命令上。

本文覆盖：

- `JDK 8`
- `MySQL`
- `Redis`
- `Nacos`
- `Elasticsearch`

可选外部依赖：

- `PostgreSQL`

## 2. 总体原则

### 2.1 安装原则

- 使用独立系统账号运行中间件
- 数据目录、日志目录、安装目录分离
- 配置文件统一收敛到固定目录
- 使用 `systemd` 托管
- 只暴露必要端口
- 先内网验证，再开放给业务机器

### 2.2 目录建议

```text
/data/middleware/
├─ jdk/
├─ mysql/
│  ├─ app/
│  ├─ data/
│  ├─ logs/
│  └─ conf/
├─ redis/
│  ├─ app/
│  ├─ data/
│  ├─ logs/
│  └─ conf/
├─ nacos/
│  ├─ app/
│  ├─ logs/
│  └─ conf/
└─ elasticsearch/
   ├─ app/
   ├─ data/
   ├─ logs/
   └─ conf/
```

### 2.3 账号建议

```text
mysql:mysql
redis:redis
nacos:nacos
elastic:elastic
```

## 3. 版本选择建议

本文不强行写死版本号，生产应以公司批准版本为准。建议采用：

- `JDK 8` LTS 发行版
- `MySQL 5.7` 或公司标准 8.x
- `Redis 6.x/7.x`
- `Nacos 2.2.x` 或公司当前统一版本
- `Elasticsearch 8.x` 或公司统一版本

说明：

- 仓库现网兼容思路更接近 `auth-all + Java8 + Nacos2.x`
- 如果中间件版本升级，先验证与 `auth-all`、Python 客户端、ES 客户端兼容性

## 4. JDK 8 二进制部署

### 4.1 安装

```bash
mkdir -p /data/middleware/jdk
tar -xzf jdk-8uXXX-linux-x64.tar.gz -C /data/middleware/jdk
ln -sfn /data/middleware/jdk/jdk1.8.0_xxx /data/middleware/jdk/current
```

### 4.2 环境变量

文件：`/etc/profile.d/star-devops-java.sh`

```bash
export JAVA_HOME=/data/middleware/jdk/current
export JRE_HOME=$JAVA_HOME/jre
export PATH=$JAVA_HOME/bin:$PATH
```

生效：

```bash
source /etc/profile.d/star-devops-java.sh
java -version
```

## 5. MySQL 二进制部署

### 5.1 适用范围

- `auth-all` 资源库
- `Nacos` 配置库
- 其他平台关系型配置库

### 5.2 安装目录准备

```bash
groupadd mysql || true
useradd -r -g mysql -s /sbin/nologin mysql || true

mkdir -p /data/middleware/mysql/{app,data,logs,conf,tmp}
chown -R mysql:mysql /data/middleware/mysql
```

### 5.3 解压官方 generic binary

```bash
tar -xzf mysql-<version>-linux-glibc2.12-x86_64.tar.gz -C /data/middleware/mysql/app
ln -sfn /data/middleware/mysql/app/mysql-<version>-linux-glibc2.12-x86_64 /data/middleware/mysql/current
```

### 5.4 my.cnf 示例

文件：`/data/middleware/mysql/conf/my.cnf`

```ini
[mysqld]
user=mysql
port=3306
basedir=/data/middleware/mysql/current
datadir=/data/middleware/mysql/data
socket=/data/middleware/mysql/tmp/mysql.sock
pid-file=/data/middleware/mysql/tmp/mysql.pid
log-error=/data/middleware/mysql/logs/error.log
character-set-server=utf8mb4
collation-server=utf8mb4_general_ci
default-time-zone=+08:00
max_connections=1000
innodb_buffer_pool_size=4G
skip_name_resolve=ON

[client]
socket=/data/middleware/mysql/tmp/mysql.sock
default-character-set=utf8mb4
```

### 5.5 初始化

```bash
/data/middleware/mysql/current/bin/mysqld \
  --defaults-file=/data/middleware/mysql/conf/my.cnf \
  --initialize \
  --user=mysql
```

记录初始化输出中的临时 root 密码。

### 5.6 systemd

文件：`/etc/systemd/system/mysql-star-devops.service`

```ini
[Unit]
Description=mysql-star-devops
After=network.target

[Service]
User=mysql
Group=mysql
Type=forking
ExecStart=/data/middleware/mysql/current/bin/mysqld_safe --defaults-file=/data/middleware/mysql/conf/my.cnf
ExecStop=/data/middleware/mysql/current/bin/mysqladmin --socket=/data/middleware/mysql/tmp/mysql.sock -uroot -p shutdown
Restart=always
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

### 5.7 初始化业务库

建议至少创建：

```text
aiops_resource
nacos
```

### 5.8 验收

```bash
systemctl start mysql-star-devops
systemctl status mysql-star-devops --no-pager
mysql -uroot -p -S /data/middleware/mysql/tmp/mysql.sock -e 'show databases;'
```

## 6. Redis 本机服务化部署

### 6.1 说明

Redis 官方主流发布形态长期以源码包为主，因此这里的“二进制部署”采用：

- 一次性编译生成二进制
- 生产运行使用本机二进制和 `systemd`

不建议生产长期直接使用容器临时进程。

### 6.2 准备目录

```bash
groupadd redis || true
useradd -r -g redis -s /sbin/nologin redis || true

mkdir -p /data/middleware/redis/{app,data,logs,conf}
chown -R redis:redis /data/middleware/redis
```

### 6.3 编译并安装

```bash
tar -xzf redis-<version>.tar.gz -C /data/middleware/redis/app
cd /data/middleware/redis/app/redis-<version>
make
ln -sfn /data/middleware/redis/app/redis-<version> /data/middleware/redis/current
```

### 6.4 redis.conf 示例

文件：`/data/middleware/redis/conf/redis.conf`

```conf
bind 0.0.0.0
protected-mode yes
port 6379
daemonize no
pidfile /data/middleware/redis/redis.pid
dir /data/middleware/redis/data
logfile /data/middleware/redis/logs/redis.log
appendonly yes
requirepass replace-me
timeout 0
tcp-keepalive 300
```

### 6.5 systemd

文件：`/etc/systemd/system/redis-star-devops.service`

```ini
[Unit]
Description=redis-star-devops
After=network.target

[Service]
Type=simple
User=redis
Group=redis
ExecStart=/data/middleware/redis/current/src/redis-server /data/middleware/redis/conf/redis.conf
ExecStop=/data/middleware/redis/current/src/redis-cli -a replace-me shutdown
Restart=always
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

### 6.6 验收

```bash
systemctl start redis-star-devops
redis-cli -a replace-me ping
```

## 7. Nacos 二进制部署

### 7.1 适用范围

- `auth-all` 配置中心
- 平台统一通用配置中心
- 后续 `cpo-*` 微服务配置源

### 7.2 关键原则

- 生产使用外部 `MySQL` 存储
- 不使用内嵌数据库
- 推荐通过 `Nacos` 管理台或 OpenAPI 管理配置
- 不建议生产直接改 `nacos.config_info` 表

### 7.3 准备目录

```bash
groupadd nacos || true
useradd -r -g nacos -s /sbin/nologin nacos || true

mkdir -p /data/middleware/nacos/{app,logs,conf}
chown -R nacos:nacos /data/middleware/nacos
```

### 7.4 解压

```bash
tar -xzf nacos-server-<version>.tar.gz -C /data/middleware/nacos/app
ln -sfn /data/middleware/nacos/app/nacos /data/middleware/nacos/current
```

### 7.5 外部数据库准备

在 `MySQL` 中执行 `Nacos` 官方初始化 SQL，创建：

```text
nacos
```

### 7.6 application.properties 核心配置

文件：`/data/middleware/nacos/current/conf/application.properties`

```properties
server.servlet.contextPath=/nacos
server.port=8848

spring.datasource.platform=mysql
db.num=1
db.url.0=jdbc:mysql://127.0.0.1:3306/nacos?characterEncoding=utf8&connectTimeout=1000&socketTimeout=3000&autoReconnect=true
db.user.0=nacos
db.password.0=replace-me

nacos.core.auth.enabled=true
nacos.core.auth.server.identity.key=serverIdentity
nacos.core.auth.server.identity.value=replace-me
nacos.istio.mcp.server.enabled=false
```

### 7.7 systemd

文件：`/etc/systemd/system/nacos.service`

```ini
[Unit]
Description=nacos
After=network.target mysql-star-devops.service

[Service]
Type=simple
User=nacos
Group=nacos
WorkingDirectory=/data/middleware/nacos/current
Environment=MODE=standalone
ExecStart=/data/middleware/nacos/current/bin/startup.sh -m standalone
ExecStop=/data/middleware/nacos/current/bin/shutdown.sh
Restart=always
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

### 7.8 当前项目命名空间和配置约定

建议在生产环境保留以下基础约定：

```text
namespace: st-observable
group: auth-all
dataId: application.yaml
```

并新增：

```text
cpo-ai-productivity-common.yaml
cpo-feishu-collector-plugin.yaml
```

### 7.9 验收

```bash
systemctl start nacos
curl -I http://127.0.0.1:8848/nacos/
```

登录管理台后确认：

- 命名空间存在
- `auth-all/application.yaml` 已导入
- 数据源为外部 `MySQL`

## 8. Elasticsearch 二进制部署

### 8.1 适用范围

- 人效原始事件
- 日报摘要
- 事项统计
- 短期检索

### 8.2 准备目录

```bash
groupadd elastic || true
useradd -r -g elastic -s /sbin/nologin elastic || true

mkdir -p /data/middleware/elasticsearch/{app,data,logs,conf}
chown -R elastic:elastic /data/middleware/elasticsearch
```

### 8.3 解压

```bash
tar -xzf elasticsearch-<version>-linux-x86_64.tar.gz -C /data/middleware/elasticsearch/app
ln -sfn /data/middleware/elasticsearch/app/elasticsearch-<version> /data/middleware/elasticsearch/current
```

### 8.4 elasticsearch.yml 示例

文件：`/data/middleware/elasticsearch/conf/elasticsearch.yml`

```yaml
cluster.name: star-devops-es
node.name: es-01
path.data: /data/middleware/elasticsearch/data
path.logs: /data/middleware/elasticsearch/logs
network.host: 0.0.0.0
http.port: 9200
discovery.type: single-node
xpack.security.enabled: true
```

### 8.5 jvm.options 建议

按机器内存设置，常见建议：

```text
Xms4g
Xmx4g
```

且两者必须相同。

### 8.6 systemd

文件：`/etc/systemd/system/elasticsearch-star-devops.service`

```ini
[Unit]
Description=elasticsearch-star-devops
After=network.target

[Service]
Type=simple
User=elastic
Group=elastic
WorkingDirectory=/data/middleware/elasticsearch/current
Environment=ES_PATH_CONF=/data/middleware/elasticsearch/conf
ExecStart=/data/middleware/elasticsearch/current/bin/elasticsearch
Restart=always
RestartSec=5
LimitNOFILE=65535
LimitMEMLOCK=infinity

[Install]
WantedBy=multi-user.target
```

### 8.7 当前项目索引约定

建议至少保留以下索引前缀：

```text
cpo-productivity-chat-raw-*
cpo-productivity-summary-*
```

并配置保留策略：

- 原始事件：`15d`
- 汇总/日报：`180d`

### 8.8 验收

```bash
systemctl start elasticsearch-star-devops
curl -u elastic:replace-me http://127.0.0.1:9200
```

## 9. PostgreSQL 说明

当前项目并不要求自建 `PostgreSQL` 作为核心平台中间件，但 `cpo-ai-productivity-service` 后续会查询外部工单库。

因此生产部署建议是：

- 优先接入现有工单 `PostgreSQL`
- 只在业务方没有现成库时再单独建设

如果后续需要在本项目侧独立落地 `PostgreSQL`，应新增独立部署文档，不与本篇混写。

## 10. 防火墙与端口建议

| 组件 | 端口 | 建议开放范围 |
| --- | ---: | --- |
| MySQL | 3306 | 仅后端和 Nacos 访问 |
| Redis | 6379 | 仅后端访问 |
| Nacos | 8848 | 仅服务节点与运维节点 |
| Nacos gRPC | 9848/9849 | 仅服务节点 |
| Elasticsearch | 9200 | 仅后端服务 |

原则：

- 不把 `MySQL`、`Redis`、`ES` 直接暴露公网
- `Nacos` 管理台仅开放给运维和服务节点

## 11. 配置备份建议

### 11.1 MySQL

- 每日逻辑备份
- 每周物理备份
- 升级前全量备份

### 11.2 Redis

- 保留 `appendonly.aof`
- 升级前复制 `data/` 目录

### 11.3 Nacos

- 升级前导出命名空间配置
- 同时备份 `nacos` 数据库

### 11.4 Elasticsearch

- 使用快照仓库做索引快照
- 变更 ILM 前先验证快照可恢复

## 12. 最终验收清单

- `JDK` 安装正确
- `MySQL`、`Redis`、`Nacos`、`Elasticsearch` 已纳入 `systemd`
- 所有服务均使用独立目录和独立账号
- 业务服务已能访问对应中间件
- `auth-all` 已从 `Nacos` 成功读取配置
- `cpo-ai-productivity-service` 已连通 `ES` 和 `AstrBot`
- 配置备份和日志留存策略已建立

# AI人效自动化功能汇总与安全授权说明

更新时间：2026-08-11

## 1. 功能汇总

当前规划中的核心功能：

- 飞书聊天采集
- 聊天统计分析
- 事项统计分析
- AI 日报生成
- AI 周报生成
- 待办看板
- 工单运营分析
- 文档统计
- 会议统计

## 2. 当前已实现部分

- 用户 OAuth 授权
- 聊天原始明细采集
- 聊天聚合报告
- 前端服务入口与个人运营首页
- AI 日报生成接口

## 3. 飞书授权范围说明

当前聊天采集需要以下用户授权权限：

- `offline_access`
- `im:chat:readonly`
- `im:message:readonly`
- `im:message.p2p_msg:get_as_user`
- `im:message.group_msg:get_as_user`

授权原则说明：

- 以上权限不是平台后台静默代开。
- 必须由用户本人在飞书授权页显式确认授权。
- 未授权的用户，不进入真实聊天采集链路。
- 用户撤销授权、`refresh_token` 过期或应用权限被回收后，采集器会停止真实采集，并向平台写入失败通知。

用途说明：

- `offline_access`
  - 用于自动刷新 token
- `im:chat:readonly`
  - 用于读取用户可见会话列表
- `im:message:readonly`
  - 用于读取消息基础内容
- `im:message.p2p_msg:get_as_user`
  - 用于读取单聊消息
- `im:message.group_msg:get_as_user`
  - 用于读取群聊消息

## 4. 安全设置要求

飞书应用后台必须配置：

- 重定向 URL
  - `http://127.0.0.1:17891/callback`
- 刷新 `user_access_token` 开关
- 权限开通后发布应用

同时要明确：

- 重定向地址必须和授权链接中的 `redirect_uri` 完全一致。
- 当前默认本地回调是 `127.0.0.1:17891`，只监听本机环回，不对外网暴露。
- 普通用户页面只展示配置指导，不保存用户本地机器人密钥、App Secret 和 token。

## 5. 数据安全边界

### 5.1 当前原始数据

当前会保留：

- 聊天原始消息明细
- 聚合统计报告

默认保留：

- 原始事件 15 天
- 聚合统计 180 天

后续正式落地原则：

- 原始事件进入 ES
- 最终统计结果也进入 ES
- AI 事项抽取结果进入 ES
- AI 日报 / 周报摘要进入 ES

共享 MySQL 只保留用户主数据，不承载各组织的人效统计结果。

### 5.2 默认排除内容

当前默认排除：

- 机器人消息
- 审批流消息
- 工作流消息
- 应用通知消息
- 系统模板消息
- 明显闲聊关键词

当前聊天统计默认不采集或不计入口径的交互包括：

- 与机器人应用的直接交互
- 审批、工作流、应用通知、系统模板消息
- 预置闲聊关键词命中的消息

### 5.3 不直接暴露的敏感信息

以下内容不应出现在普通用户下载包和前端页面：

- 飞书 App Secret
- 平台上传 token
- Elasticsearch 凭证
- 数据库密码
- AstrBot API Key

## 6. 用户权限与管理员权限

### 6.1 普通用户

普通用户应具备：

- 查看自己的采集配置指导
- 授权自己的飞书应用
- 查看自己的统计结果
- 查看自己的日报
- 管理自己的待办

### 6.2 管理员

管理员后续应具备：

- 查看所有用户统计
- 按时间范围筛选
- 按部门 / 团队聚合
- 查看事项分布与待办趋势
- 查看异常与趋势
- 管理全局配置

## 7. 后续安全建议

- 平台用户表统一维护 `feishu_open_id`
- 服务端统一入 ES，不让前端直连 ES
- 最终统计结果也统一入 ES，避免和原始事件分裂到不同主存储
- 原始事件短保留，聚合结果长保留
- AI 输出保留人工审阅链路
- 后续对外展示只展示必要字段
- 采集失败、授权失败、回传失败统一进入平台通知中心，必要时再由服务端 webhook 转发到统一通知渠道
- 多组织推广时，各组织独立部署后端 + ES，共享 MySQL 用户表即可

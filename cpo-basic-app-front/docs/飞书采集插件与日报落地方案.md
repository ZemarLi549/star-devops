# 鑫图平台飞书采集插件与日报落地方案

## 1. 目标

为鑫图平台建设一个“个人部署、平台汇聚、AstBot 汇总”的飞书协同采集方案，满足以下目标：

- 用户自己下载并部署插件到本机。
- 采集个人单聊、群聊、被 `@`、会议和文档贡献。
- 用户可在平台页面配置群聊过滤、关键字过滤和分析范围。
- 采集数据集中上报到平台，短期事件保存在 ES，默认保留 7 天。
- 平台使用 AstBot 相关 AI 能力做日报摘要、趋势分析和结果展示。

## 2. 架构分层

```text
用户电脑
  cpo-feishu-collector-plugin
    -> 拉取 Nacos 公共配置
    -> 读取本地私有凭据/缓存
    -> 采集飞书协同元数据
    -> 上报到 xintu-gateway

平台服务
  xintu-gateway
  xintu-auth
  xintu-productivity-api
  xintu-productivity-worker
  xintu-feishu-connector
  xintu-summary-service
  xintu-astrbot-adapter

存储
  MySQL/PostgreSQL: 配置、规则、任务、日报、审计
  Elasticsearch: 7 天原始事件与摘要检索
```

## 3. Nacos 配置中心约定

所有通用配置走 Nacos，建议 namespace 继续使用现有环境约定，不在仓库写死环境地址。

推荐 dataId：

```text
cpo-productivity-common.yaml
cpo-feishu-collector-plugin.yaml
cpo-feishu-connector.yaml
cpo-summary-service.yaml
```

推荐分工：

- `cpo-productivity-common.yaml`
  - 平台上报网关地址
  - 默认时区
  - 采集批次大小
  - 限流与重试策略
  - ES 索引前缀与保留天数
- `cpo-feishu-collector-plugin.yaml`
  - 插件心跳周期
  - 本地缓存目录
  - 采集窗口
  - 上报接口路径
  - 功能开关
- `cpo-summary-service.yaml`
  - 日报模板版本
  - 摘要触发时间
  - AstBot 工具路由开关

敏感项处理原则：

- 飞书应用密钥、机器人密钥、数据库密码、ES 密码不写前端、不写插件包默认值。
- 平台侧敏感配置只放 Nacos 密文能力或环境变量。
- 插件侧仅保存当前用户自己的短期上报 token 和本地缓存。

## 4. 插件采集范围

插件按用户授权范围采集以下数据：

- 单聊次数、发送消息数、接收消息数。
- 群聊次数、群消息发送数、群消息接收数。
- 被 `@` 次数、发生群、发生时间。
- 会议次数、会议时长、参与角色。
- 文档创建、编辑、评论和协作者贡献计数。

第一阶段默认采集元数据和最小必要摘要，不长期保留完整正文。

## 5. 用户过滤规则

平台为每个用户提供单独管理页，至少支持：

- 包含群聊列表
- 排除群聊列表
- 包含关键字
- 排除关键字
- 是否允许读取正文做主题分析
- 统计时间范围
- 是否纳入会议
- 是否纳入文档

推荐页面入口：

```text
/control/productivity-config
/productivity/filter-rules
/productivity/chat-overview
/productivity/meeting-overview
/productivity/document-overview
/productivity/daily-reports
```

其中 `/control/productivity-config` 是当前已落地的用户自助配置入口，先按当前登录用户做本地隔离保存，后续再平滑切换为后端配置接口和 Nacos 下发。

## 6. 存储策略

推荐双存储：

- ES 保存短期事件和话题摘要，默认 7 天。
- MySQL / PostgreSQL 保存配置、状态、聚合结果和审计。

不建议把所有数据都只存 ES，原因是：

- 过滤规则、用户授权、插件注册、同步任务和日报确认状态更适合关系库。
- ES 更适合高频检索、时间窗口分析和短期明细回放。

推荐 ES 索引：

```text
cpo-feishu-chat-event-YYYY.MM.DD
cpo-feishu-mention-event-YYYY.MM.DD
cpo-feishu-topic-summary-YYYY.MM.DD
cpo-daily-report-search-YYYY.MM.DD
```

推荐 ILM：

- `0-2d` 热索引
- `3-7d` 温索引
- `>7d` 删除

## 7. AstBot 日报链路

```text
插件上报
  -> 平台落 ES / 聚合表
  -> xintu-summary-service 读取过滤后的统计数据
  -> 生成日报草稿
  -> xintu-astrbot-adapter 调 AstBot 工具链
  -> 返回日报摘要、工作主题、待办和风险
  -> 用户审阅确认
```

关键约束：

- AstBot 只读取用户已授权且已过滤的数据。
- 优先使用聚合结果和脱敏摘要，不直接把全量聊天正文喂给模型。
- 每次摘要生成记录模型版本、时间范围、过滤规则和来源批次。

## 8. 下载包交付形式

建议平台提供以下下载物：

```text
cpo-feishu-collector-plugin-linux-amd64.tar.gz
cpo-feishu-collector-plugin-macos-arm64.tar.gz
cpo-feishu-collector-plugin-windows-amd64.zip
```

下载包至少包含：

- 可执行程序
- `config/application.example.yaml`
- `README.md`
- `bin/start.sh`
- `bin/stop.sh`

## 9. 首批落地建议

第一批先做这几个能力：

1. 插件下载入口和实例注册。
2. 用户过滤规则管理页。
3. 单聊、群聊、被 `@` 聚合统计。
4. ES 7 天滚动索引。
5. 日报草稿生成与审阅页。

会议和文档贡献统计可以紧随第二批接入。

## 3. Nacos 配置要求

通用配置统一走 Nacos 配置中心，不在前端仓库硬编码。

当前 `auth-all` 依赖的关键配置项如下：

```yaml
authentication:
  type: inner
  login-mode: LOCAL
  ldap:
    url: ""
    base-dn: ""
    bind-dn: ""
    bind-password: ""
    user-search-base: ""
    user-search-filter: "(sAMAccountName={0})"
    connect-timeout-ms: 5000
    read-timeout-ms: 5000

inner:
  auth:
    excludeUrls: /login,/loginMode,/captcha,/logout,/refreshToken,/loginInfo,/authChange,/authentication/authorization/applications,/authentication/authorization/dataGroups,/authentication/authorization/dataGroupName,/permission/**,/metaAndMenu/**,/initCipherData
  apiPermission:
    excludeUrls: /auth/workspace,/auth/guideState,/auth/userBaseInfo,/auth/updateUser,/auth/updatePassword,/auth/menu
```

登录模式说明：

- `LOCAL`：仅本地登录
- `LDAP`：仅 LDAP 登录
- `MIXED`：本地和 LDAP 混合登录

## 4. 数据库增量

本轮 LDAP 和身份字段接入后，`aiops_resource.sys_user` 必须先执行增量 SQL，否则 `auth-all` 无法启动。

执行脚本：

```text
auth-all/sql_dir/aiops_resource_user_identity_upgrade.sql
```

脚本内容作用：

- 新增 `feishu_user_id`
- 新增 `it_workbench_user_id`
- 新增 `identity_source`
- 新增 `ldap_account`

如果未执行，启动时会出现类似错误：

```text
Unknown column 'feishu_user_id' in 'field list'
```

## 5. auth-all 启动步骤

### 5.1 编译

```bash
mvn -f /home/kali/ai_study/star-devops/auth-all/pom.xml -pl starter -am -DskipTests package
```

### 5.2 重要说明

当前项目的 `mvn package` 会刷新：

- `auth-all/starter/target/auth-all.zip`

但不会稳定覆盖已经解压好的运行目录：

- `auth-all/starter/target/auth-all/lib/*.jar`

因此如果直接在已存在的 `target/auth-all` 目录里启动，可能出现：

- 源码已经变更
- 模块 jar 仍然是旧版本
- 运行结果和源码不一致

本轮联调已经确认过这个问题。

稳妥做法二选一：

1. 每次打包后删除旧运行目录，重新解压最新 `auth-all.zip`
2. 或把最新模块 jar 手工覆盖到 `target/auth-all/lib`

本轮实际覆盖过的 jar：

- `auth-service-1.0-SNAPSHOT.jar`
- `resource-manager-service-1.0-SNAPSHOT.jar`
- `common-1.0-SNAPSHOT.jar`

### 5.3 启动命令

在目录：

```text
/home/kali/ai_study/star-devops/auth-all/starter/target/auth-all
```

执行：

```bash
java -Dspring.config.additional-location=file:./config/ -cp 'auth-all.jar:lib/*' com.iflytek.itsc.auth.AuthApplication
```

### 5.4 启动成功标志

## 8. LDAP 登录模式说明

当前口径已经统一：

- 用户管理中的账号字段就是 LDAP 登录账号本身
- 不单独维护一个前端可编辑的 `ldapAccount` 字段
- 后端在 `identitySource=LDAP` 时自动写入 `ldap_account=account`

登录页由后台配置控制登录方式：

- 本地登录
- LDAP 登录
- 混合登录

前端已经接入：

- 登录页启动时请求 `/auth/loginMode`
- 根据返回结果展示本地登录或 LDAP 登录入口

## 9. 常见问题

### 9.1 `/auth/loginMode` 返回异常

先检查两件事：

1. 当前运行目录中的 `lib/auth-service-1.0-SNAPSHOT.jar` 是否为最新版本
2. `inner.auth.excludeUrls` 是否包含 `/loginMode`

### 9.2 auth-all 启动失败并提示缺字段

说明数据库没有执行增量脚本，执行：

```text
auth-all/sql_dir/aiops_resource_user_identity_upgrade.sql
```

### 9.3 前端能打开但首页部分接口 404

这是当前阶段的正常现象。

原因是：

- 目前只启动了 `auth-all`
- 工单、CMDB、日志、告警、Zabbix 聚合等后续微服务还没有接入
- 基座首页若请求这些后端，会出现缺服务返回

### 9.4 修改后端源码但运行效果没变化

优先排查：

- 是不是只重新编译了 Maven 模块
- 但没有刷新 `starter/target/auth-all/lib` 中的旧 jar

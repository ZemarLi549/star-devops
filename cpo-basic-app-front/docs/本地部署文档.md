# cpo 微服务本地部署文档

## 1. 目标和范围

本文档用于在当前开发机启动第一阶段的前后端基础链路：

```text
浏览器
  -> cpo-basic-app-front (Vite :80)
  -> /auth 代理
  -> auth-all (:9004/auth)
  -> Nacos (:8848)、MySQL (:3306)、Redis (:6379)
```

本阶段只启动认证服务和基础前端。观测、日志、指标、链路、告警等子应用目录已经统一为 `cpo-` 前缀，但对应后端服务未在本阶段启动。

## 4. Nacos 配置关系

`auth-all` 的启动配置见 `auth-all/pack/config/bootstrap.yml` 和构建产物目录下的 `config/bootstrap.yml`。关键配置如下：

```yaml
spring:
  application:
    name: auth
  cloud:
    nacos:
      config:
        namespace: st-observable
        group: auth-all
        data-id: application.yaml
        file-extension: yaml
      discovery:
        namespace: st-observable
```

本机启动时使用环境变量覆盖 Nacos 地址、账号、密码和 namespace：

```bash
export CONFIG_NACOS_SERVER_ADDR=127.0.0.1:8848
export CONFIG_NACOS_USERNAME=nacos
export CONFIG_NACOS_PASSWORD=nacos
export CONFIG_NACOS_NAMESPACE=st-observable
```

Nacos 中的 `application.yaml` 负责提供认证服务的端口、上下文路径、Redis 和 MySQL 配置。namespace `st-observable` 是现有配置中心的运行契约，不因工程目录从 `stc-` 改为 `cpo-` 而改名。

## 5. 启动 Nacos

如果 Nacos 已经运行，只需验证健康状态：

```bash
curl -fsS http://127.0.0.1:8848/nacos/v1/console/health/liveness
```

预期输出：

```text
OK
```

当前本机 Docker 容器名为 `star-nacos`，镜像为 `nacos/nacos-server:v2.2.0`。如果容器未运行，使用项目已有的 Nacos/MySQL 部署方式恢复，不要重复初始化已经存在的基础数据库。

## 6. 启动 auth-all

### 6.1 使用已打包产物

`auth-all.jar` 是瘦包，必须带上同目录 `lib` 下的依赖，不能只执行 `java -jar auth-all.jar`：

```bash
cd /home/kali/ai_study/star-devops/auth-all/starter/target/auth-all

export CONFIG_NACOS_SERVER_ADDR=127.0.0.1:8848
export CONFIG_NACOS_USERNAME=nacos
export CONFIG_NACOS_PASSWORD=nacos
export CONFIG_NACOS_NAMESPACE=st-observable

java \
  -Dspring.config.additional-location=file:./config/ \
  -cp 'auth-all.jar:lib/*' \
  com.iflytek.itsc.auth.AuthApplication
```

启动成功后验证端口：

```bash
nc -vz 127.0.0.1 9004
curl -sS -i http://127.0.0.1:9004/auth/
```

根路径返回业务错误 JSON 是当前服务行为，不代表进程未启动；真正的判断标准是端口监听和登录接口可用。

### 6.2 重新构建

只有在需要重新打包 `auth-all` 时才执行构建：

```bash
cd /home/kali/ai_study/star-devops/auth-all
mvn clean package -DskipTests -s ./maven_settings.xml
```

如果 Maven 报 `depend.iflytek.com` 无法解析，需要先接入对应内网/VPN 或准备离线 Maven 依赖；这不是前端 Node 环境问题。

## 7. 启动 cpo-basic-app-front

### 7.1 安装依赖

```bash
cd /home/kali/ai_study/star-devops/cpo-basic-app-front
export PATH=/home/kali/.hermes/node/bin:$PATH
npm ci
```

`npm ci` 会删除并按 `package-lock.json` 重建 `node_modules`，可避免把 Windows 版 `esbuild` 带到 Linux 环境。

### 7.2 启动开发服务

优先使用项目脚本：

```bash
npm run dev
```

如果 `.bin/vite` 没有执行权限，使用绝对 Node 路径启动：

```bash
/home/kali/.hermes/node/bin/node \
  node_modules/vite/bin/vite.js \
  --mode development \
  --host 0.0.0.0 \
  --port 80
```

Vite 配置中的默认代理目标是 `http://127.0.0.1:9004/`，因此浏览器访问前端时使用同源地址即可，不要把前端请求直接改成跨域的 `9004` 地址。

## 8. 启动验证

### 8.1 页面

```bash
curl -fsSI http://127.0.0.1/
```

浏览器访问 `http://127.0.0.1/`，预期显示登录页。

### 8.2 本地登录

当前已验证的本地开发账号：

```text
账号：admin
密码：Cxmt#666
```

前端不会把明文密码发送给后端，而是先计算一次 MD5：

```text
MD5("Cxmt#666") = 3438684223ee87988e2afbba6dbfc861
```

接口验证示例：

```bash
curl -sS \
  -H 'Content-Type: application/json' \
  -X POST \
  http://127.0.0.1/auth/login \
  -d '{"account":"admin","password":"3438684223ee87988e2afbba6dbfc861"}'
```

预期响应中的 `data.success` 为 `true`，并包含 token 信息。

### 8.3 登录后的基础请求

浏览器登录后应至少成功调用：

```text
POST /auth/login
GET  /auth/workspace
GET  /auth/userBaseInfo
GET  /auth/menu
```

当前验证结果均为 HTTP `200`，登录后路由跳转到 `/control`。

## 9. 当前已知边界

首页还会尝试请求以下业务后端：

```text
POST /graphql
POST /alarm-manager/analysis/level
POST /alarm-manager/statistics/task
```

本阶段没有启动对应观测/告警后端，因此这些请求可能返回 `404`，并触发首页观测组件的运行时错误。认证链路和基础页面仍可使用；启动完整平台前，需要继续启动对应 `cpo-observe-*` 子应用及其后端微服务。

此外，浏览器控制台存在现有依赖警告，包括 qiankun `globalState` 弃用提示和 Element Plus `custom-class` 弃用提示。本次环境启动未修改业务代码处理这些历史问题。

## 10. 停止服务

前端在启动终端使用 `Ctrl+C` 停止。停止 `auth-all` 时，优先结束本次启动的 Java 进程：

```bash
ps -ef | rg 'com.iflytek.itsc.auth.AuthApplication'
kill <PID>
```

不要使用全局 `pkill java`，避免影响 Nacos 或其他本机服务。

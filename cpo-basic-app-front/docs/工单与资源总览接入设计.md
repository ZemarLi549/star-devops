# 鑫图平台工单与资源总览接入设计

## 1. 目标

工作台首页只展示个人纵览，不承载完整工单、CMDB 或监控操作页面。用户可以在首页按时间窗口查看个人处理工单、飞书协同、文档会议、负责应用和资源数量，并通过服务入口进入领域详情。

首页预留的服务入口：

```text
工单运营
CMDB 资源运维
Zabbix 集中管理
智能助手平台
AI 人效自动化系统
```

## 2. 数据源边界

### 2.1 三方工单 PostgreSQL

用户后续提供 SQL 后，由后端 `xintu-workorder-connector` 或 `xintu-productivity-api` 负责执行查询和聚合，前端只接收统计结果。

建议后端统一输出：

```json
{
  "timeRange": {
    "startAt": "2026-08-03T00:00:00+08:00",
    "endAt": "2026-08-10T23:59:59+08:00",
    "timeZone": "Asia/Shanghai"
  },
  "summary": {
    "processingCount": 0,
    "completedCount": 0,
    "collaboratedCount": 0,
    "slaRiskCount": 0
  },
  "detailEntry": "/api/workorders/my"
}
```

查询必须使用参数化 SQL，前端不传 SQL，不传任意表名或字段名。工单详情接口必须按当前用户、租户、角色和数据范围做后端鉴权。

### 2.2 飞书协同数据

复用 [AI人效自动化系统设计.md](./AI人效自动化系统设计.md) 中的连接器和授权边界：

- 单聊次数。
- 群聊次数。
- 被 `@` 次数。
- 参与文档数量和贡献动作。
- 参与会议数量、总时长和会议详情入口。

默认不保存完整聊天正文，首页只显示聚合指标。详情入口需要继承同一时间范围、群聊过滤和关键字过滤规则。

### 2.3 CMDB

CMDB 服务提供个人负责的应用系统、服务器、网络和其他资源数量。建议返回资源类型、数量、健康状态和详情入口，不在首页加载完整资源列表。

```json
{
  "applications": 0,
  "servers": 0,
  "databases": 0,
  "otherResources": 0,
  "detailEntry": "/api/cmdb/my-resources"
}
```

### 2.4 多套 Zabbix 与 zabbix-watcher

新增 `xintu-zabbix-gateway`，统一对接多个 Zabbix 数据中心，并将开源 `zabbix-watcher` 作为集中管理和事件归并适配层：

```text
Zabbix DC 1
Zabbix DC 2
Zabbix DC N
  -> xintu-zabbix-gateway
  -> zabbix-watcher adapter
  -> 统一主机、监控项、告警和资源视图
```

首页只展示：

- 个人负责机器数量。
- 机器在线/异常数量。
- 内存和磁盘容量概览。
- 待处理告警数量。
- 个人机器详情入口。

内存和磁盘的实时详情通过后端按需查询，不能在浏览器中保存 Zabbix 凭据。

## 3. 首页接口契约

建议新增一个聚合接口，减少首页请求数量：

```text
GET /api/workbench/overview?startAt=&endAt=&timeZone=
```

响应建议：

```json
{
  "timeRange": {},
  "workOrders": {
    "processingCount": 0,
    "completedCount": 0,
    "collaboratedCount": 0,
    "detailEntry": "/api/workorders/my"
  },
  "feishu": {
    "oneToOneCount": 0,
    "groupChatCount": 0,
    "mentionCount": 0,
    "documentCount": 0,
    "meetingCount": 0,
    "meetingMinutes": 0,
    "detailEntry": "/api/productivity/feishu/overview"
  },
  "cmdb": {
    "applicationCount": 0,
    "serverCount": 0,
    "resourceCount": 0,
    "detailEntry": "/api/cmdb/my-resources"
  },
  "zabbix": {
    "hostCount": 0,
    "problemCount": 0,
    "memoryBytes": 0,
    "diskBytes": 0,
    "detailEntry": "/api/zabbix/my-hosts"
  }
}
```

接口必须支持：

```text
startAt
endAt
timeZone
userId
tenantId
workspaceId
```

`userId`、`tenantId` 和 `workspaceId` 不能以客户端参数作为最终授权依据，后端应优先使用会话上下文并校验请求范围。

## 4. 服务入口路由

建议使用稳定的业务路由，不把数据库、Zabbix 地址或第三方工具细节暴露到前端：

```text
/work-order-ops
/cmdb-resource-ops
/zabbix-center
/assistant
/productivity
```

每个入口对应一个前端子应用或领域路由，统一经过 `xintu-gateway` 鉴权。当前入口卡片可以先展示“详情入口”和数据源说明，待后端路由完成后再从配置中心开放。

## 5. 缓存和刷新策略

- 首页聚合数据建议短缓存 30 至 120 秒。
- 详情接口按需加载，不在首页自动拉取大列表。
- 时间范围切换需要取消上一个未完成请求，避免旧响应覆盖新范围。
- PG、飞书、CMDB、Zabbix 任一数据源失败时，单独返回数据源状态，不影响其他指标展示。
- 每个数据源返回 `sourceStatus`、`lastSyncAt` 和 `requestId`，方便排障和审计。

## 6. 安全要求

- PostgreSQL 工单连接信息仅在后端密文保存。
- Zabbix 凭据和 `zabbix-watcher` 配置不进入前端和日志。
- 详情入口必须继续做租户、用户和资源范围鉴权。
- 首页默认只展示个人数据，不提供未授权的团队排名。
- 资源、会议、聊天和工单数据设置独立保留期和删除策略。
- 跨源聚合写入审计日志，记录用户、范围、来源和时间窗口。

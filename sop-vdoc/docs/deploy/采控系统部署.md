## 部署说明

- 该文档适用于可观测团队现阶段向各业务线交付的星迹可观测平台部署建议和步骤
- 目前采用的云下部署方案为物理节点部署

## 部署建议

采控系统作为辅助操作系统不单独占用机器资源，可以和其他系统共享。

## 部署步骤

## 1. nodeman部署

### 获取部署包

根据CPU架构选择nodeman_service_amd64.zip 或 nodeman_service_arm64.zip部署包并解压

```shell
# 创建部署目录
mkdir -p /data/service/nodeman_service
cd /data/service/nodeman_service

# 解压
unzip  nodeman_service_amd64.zip      #amd架构
或 unzip  nodeman_service_arm64.zip    #arm架构
chmod +x st_nodeman
```


### 执行初始化sql


若选择MySQL数据库，创建mysql数据库，表不用建，程序会自动创建表。

```shell
mysql> CREATE DATABASE `bo_nodeman`  character set utf8mb4 collate utf8mb4_general_ci;
```

若选择DM达梦数据库，先创建dm数据库模式，表不用建，程序会自动创建表。

```shell
> CREATE SCHEMA "BO_NODEMAN";
```

### 编辑nodeman配置文件

```

将其中的nacos地址、端口、用户名、密码等信息换成自己的
```

2. 将发布包/nacos配置/nacos_config.zip导入（如已导入，忽略此步骤，直接去改相关配置）

## 2. gse部署

### 获取部署包

根据CPU架构选择gse_service_amd64.zip 或 gse_service_arm64.zip部署包并解压

```shell
# 创建部署目录
mkdir -p /data/service/gse_server
cd /data/service/gse_server

# 解压
unzip  gse_service_amd64.zip      #amd架构
或 unzip  gse_service_arm64.zip    #arm架构
chmod +x st_gse
```
### 编辑gse配置文件

```
vim configs/config.json
将其中的nacos地址、端口、用户名、密码等信息换成自己的
```
nacos到st-observable空间下，group为gse-service，Data Id为config.json的配置文件，修改其中的配置，配置内容如下：
redisType为：单节点：空字符串 ""； 哨兵："sentinel"; 集群："cluster";

```json
{
  "server_addr": "",
  "port": 8090,   //gse服务必须使用8090端口，不可修改，如果冲突，停掉冲突的进程
  "nodeman_domain": "st-nodeman",  // nacos中注册的服务名，不用修改
  "skip_auth": true,
  "swagger_enable": false,
  "data_base": {
    "drive": "mysql或者dm",   // 支持mysql或达梦数据库
    "host": "127.0.0.1",
    "port": "3306",
    "user": "root",
    "pwd": "xxxxxxxxx",
    "database": "bo_nodeman",
    "show_sql": false
  },
  "redis": {
    "addrs": "127.0.0.1:6379",
    "password": "xxxxxxxxx",
    "masterName": "",
    "redisType": "sentinel"
  },
 
  "log_path": "/data/logs/bk_gse",
  "mode": "dev"
}
```

### 启动gse

```shell
sh start.sh
```

### 停止gse

```shell
sh stop.sh
```

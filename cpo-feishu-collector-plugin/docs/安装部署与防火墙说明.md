# cpo-feishu-collector-plugin 安装部署与防火墙说明

本文面向需要在个人办公机、跳板机或受控终端上安装 `cpo-feishu-collector-plugin` 的用户。

目标是先把插件跑起来，再按平台后续接口逐步接入真实飞书授权、事件回传和日报总结。

## 1. 安装前提

- 操作系统支持 Linux / macOS / Windows。
- 本机已安装 Go 1.25 或更高版本，或直接使用已打好的 Go 客户端压缩包。
- 当前用户具备创建目录、写入 `data/` 和 `logs/` 的权限。
- 如果要对接平台服务端，需要能访问鑫图平台网关和 Nacos。
- 如果启用真实飞书授权和 API 采集，还需要能访问飞书开放平台。

## 2. 安装目录

建议解压到独立目录，例如：

```text
/opt/cpo-feishu-collector-plugin
```

目录结构如下：

```text
cpo-feishu-collector-plugin/
├─ bin/
├─ config/
├─ data/
├─ logs/
└─ docs/
```

## 3. 首次安装步骤

### 3.1 复制配置文件

```bash
cp config/application.example.yaml config/application.yaml
```

### 3.2 修改基础配置

重点配置项如下：

- `plugin.instance-id`
  - 插件实例 ID，建议每台机器唯一
- `plugin.tenant-id`
  - 平台租户 ID
- `plugin.user-id`
  - 当前试点用户，默认先用 `E0028517`
- `plugin.upload-token`
  - 平台回传令牌，后续由服务端下发
- `plugin.cache-dir`
  - 本地报告和缓存目录，默认 `./data`
- `plugin.log-dir`
  - 日志目录，默认 `./logs`
- `nacos.server-addr`
  - Nacos 地址
- `nacos.namespace`
  - Nacos namespace
- `platform.gateway-base-url`
  - 平台网关地址
- `filters.exclude-bot-interactions`
  - 默认 `true`，统一排除机器人、审批流、工作流和应用通知交互
- `filters.exclude-group-regexes`
  - 群聊名称正则黑名单，默认预置排除机器人、审批、通知、闲聊群
- `filters.include-group-regexes`
  - 群聊名称正则白名单，后续可按项目群、值班群等口径限定范围
- `feishu.auth-base-url`
  - 飞书认证域名，默认 `https://accounts.feishu.cn`
- `feishu.open-base-url`
  - 飞书 OpenAPI 域名，默认 `https://open.feishu.cn/open-apis`
- `feishu.auth-scopes`
  - 用户授权 scope 列表，建议按文档一次性开齐

### 3.3 飞书应用后台一次性开通项

为了避免“授权成功但采集时报权限不足”，建议你在飞书开发者后台一次性开通下面这些能力：

| 类型 | 名称 | 用途 | 当前是否必须 |
| --- | --- | --- | --- |
| 用户授权权限 | `offline_access` | 获取 `refresh_token`，支持自动刷新 token | 必须 |
| 用户授权权限 | `im:chat:readonly` | 读取当前用户可见会话列表 | 必须 |
| 用户授权权限 | `im:message:readonly` | 读取消息基础内容 | 必须 |
| 用户授权权限 | `im:message.p2p_msg:get_as_user` | 以用户身份读取单聊消息 | 必须 |
| 用户授权权限 | `im:message.group_msg:get_as_user` | 以用户身份读取群聊消息 | 必须 |
| 安全设置 | 重定向 URL | OAuth 本地回调地址白名单 | 必须 |
| 安全设置 | 刷新 `user_access_token` 开关 | 允许采集器自动刷新 token | 必须 |

说明：

- 当前链路不依赖 webhook 事件回调。
- 当前链路也不依赖机器人长连接。
- 当前链路是“用户自己授权 + 采集器主动拉取消息”。
- 如果后续新增权限，用户需要重新授权一次，新 token 才会带上新增 scope。

### 3.4 当前本地试点必须配置的回调地址

飞书开发者后台路径：

- `开发配置 -> 安全设置 -> 重定向 URL`

当前试点值：

```text
http://127.0.0.1:17891/callback
```

注意：

- 必须与授权链接中的 `redirect_uri` 完全一致
- 包括协议、IP、端口和路径
- 如果采集器和浏览器不在同一台机器，不能继续使用 `127.0.0.1`

### 3.5 运行安装脚本

```bash
bash bin/install.sh E0028517
```

脚本会自动：

- 创建 `data/` 和 `logs/`
- 创建日报历史、会议历史、文档历史、原始聊天预留目录
- 如果 `config/application.yaml` 不存在，则从样例文件复制一份
- 构建当前机器的 Go 客户端执行程序，优先复用 `~/.g/go/bin/go`
- 不直接启动采集进程，只做初始化

### 3.6 先执行授权

```bash
bash bin/authorize.sh E0028517
```

说明：

- 会启动本机回调地址
- 会打印授权链接
- 由当前用户自己在浏览器中完成飞书授权
- 授权结果只保存到当前用户自己的 token 文件

### 3.7 立即试跑一次

```bash
bash bin/collect-e0028517.sh
```

### 3.8 后台启动

```bash
bash bin/start.sh
```

脚本会自动：

- 启动后台采集进程
- 写入 PID 文件和日志文件

## 4. 日常启动与停止

### 启动

```bash
bash bin/start.sh
```

如果未授权，启动脚本不会直接后台启动，而是会提示你先执行授权命令。

## 5. 需要放行的端口

### 5.1 插件本机侧

插件本身是本地进程，不对外监听业务端口。

因此在员工电脑、跳板机或安装机器上，通常不需要额外开放入站端口。

### 5.2 插件访问平台侧的出站端口

以下端口需要允许插件机器访问：

| 目标 | 默认端口 | 方向 | 说明 |
| --- | --- | --- | --- |
| 鑫图平台网关 | `9004` | 出站 | 插件回传心跳、聊天统计、会议统计、文档统计 |
| Nacos | `8848` | 出站 | 读取公共采集配置、namespace、dataId |
| 飞书开放平台 | `443` | 出站 | 真实授权、拉取聊天数据、获取授权链接 |
| HTTPS 平台网关 | `443` | 出站 | 如果后续网关启用 HTTPS，统一改走 443 |

说明：

- 当前样例配置里的 `platform.gateway-base-url` 默认是 `http://127.0.0.1:9004`，这是本机联调地址。
- 真正部署到生产后，需要改成实际网关地址。
- 如果网关部署在内网服务器上，服务端防火墙需要允许插件机器所在网段访问对应端口。

## 6. 服务端需要开放什么

如果你要把插件连到平台服务端，服务端至少要开放：

- `9004/tcp`
  - 给插件回传用
- `8848/tcp`
  - 给插件读取 Nacos 配置用

如果后续把网关升级成 HTTPS，再开放：

- `443/tcp`

如果后续平台还会直接对接飞书开放平台，通常不需要你自己在服务端开飞书端口，直接保证服务器能访问公网 `443` 即可。

## 7. 推荐网络策略

- 插件机器只允许访问必要的服务端地址。
- 平台服务端只允许来自受控网段的插件访问。
- 不要把飞书密钥、平台 token、数据库密码写进前端或插件默认配置。
- 每个用户必须使用自己的飞书应用授权，不使用统一公共机器人采集所有人的聊天数据。
- 普通用户下载页和安装页不展示公共机器人密钥、公共飞书 App Secret、上传 token。
- 默认统一排除与机器人、工作流、审批流和应用通知机器人的聊天交互。
- 默认统一排除通用闲聊关键词，并支持群聊正则过滤。
- 只保留最小必要的上报权限和最短缓存周期。

## 9. 常见问题

### 9.1 启动后没有报告

先检查：

- `config/application.yaml` 是否存在
- `data/` 是否可写
- `plugin.user-id` 是否配置正确
- 是否已经完成 `bash bin/authorize.sh E0028517`
- 本机是否能访问飞书开放平台 `443`
- 飞书应用后台是否已经发布以下权限：
  - `offline_access`
  - `im:chat:readonly`
  - `im:message:readonly`
  - `im:message.p2p_msg:get_as_user`
  - `im:message.group_msg:get_as_user`
- 如果最近补开了权限，是否已经重新授权一次

### 9.2 无法连到平台

先检查：

- `platform.gateway-base-url` 是否写对
- 服务端是否开放 `9004/tcp`
- 本机是否允许出站访问网关

### 9.3 无法读取 Nacos

先检查：

- `nacos.server-addr` 是否写对
- 服务端是否开放 `8848/tcp`
- 账号密码、namespace、group 是否配置正确

### 9.4 为什么已经授权成功但还是 401 或权限不足

常见原因只有几类：

- 首次授权时少了必要 scope，例如漏了 `im:chat:readonly`
- 应用后台权限开了，但还没有发布
- 应用后台权限开了并已发布，但用户没有重新授权
- `refresh_token` 已失效，需要重新授权

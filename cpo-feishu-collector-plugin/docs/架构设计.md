# cpo-feishu-collector-plugin 架构设计

## 1. 定位

`cpo-feishu-collector-plugin` 是鑫图平台的个人部署式飞书协同采集插件。

它不是浏览器扩展，也不是平台后端的替代品，而是部署在用户自己设备上的轻量采集器，用于：

- 按用户授权采集飞书协同元数据。
- 在本机完成最小必要的过滤和聚合。
- 定时把统计结果回传到平台服务端。
- 为后续日报、周报和 AI 总结提供输入。

当前试点用户：

- `E0028517`

## 2. 当前真实状态

截至 2026-08-11，当前插件已经具备以下实际能力：

- 已接入真实飞书 OAuth 用户授权。
- 已支持 `user_access_token` 自动刷新。
- 已支持真实聊天拉取、过滤、聚合和本地落盘。
- 已支持按群聊名称、群聊名称正则、群 ID 进行过滤。
- 已支持输出参与人 `open_id`、群聊名称、消息明细、`@` 信息。
- 已支持把原始聊天明细保存到 `data/<userId>/raw-chat/`。

当前尚未完成的能力：

- 还没有把聊天原始事件正式写入 ES。
- 还没有正式接入文档统计链路。
- 还没有正式接入会议统计链路。
- 还没有把参与人 `open_id` 与平台用户表自动回填成账号/姓名。

## 3. 核心目标

- 每天固定 `17:30` 触发采集，统计窗口默认最近 `1` 天。
- 支持单聊、群聊、`@`、会议、文档等统计维度。
- 支持用户在页面配置过滤规则。
- 支持把采集结果回传服务端。
- 支持后续对接 AI 日报与周报总结。

## 4. 组件划分

```text
cpo-feishu-collector-plugin
├─ bin/
│  ├─ collector.mjs      # 插件主程序，负责调度、采集、持久化、上报
│  ├─ start.sh           # 启动脚本
│  └─ stop.sh            # 停止脚本
├─ config/
│  └─ application.example.yaml  # 本地配置样例
├─ data/                 # 本地缓存与报告输出
├─ logs/                 # 运行日志
└─ docs/
   ├─ 架构设计.md
   └─ 使用说明.md
```

## 5. 运行模型

插件当前采用“内置守护调度 + 本地聚合 + 可选回传”的方式：

1. 启动时读取本地配置文件和环境变量。
2. 默认以 `17:30` 作为每天采集时间。
3. 以用户授权身份拉取真实聊天数据。
4. 应用本地过滤规则，排除机器人、系统模板、审批通知、闲聊噪声。
5. 把报告写入本地 `data/<userId>/`。
6. 把原始聊天明细写入 `data/<userId>/raw-chat/`。
7. 如配置了服务端地址，则向平台网关回传。

说明：

- 当前默认使用插件内置守护进程，不要求用户自己写 `crontab`。
- `crontab` 仍可作为可选部署方式，但不是当前默认方案。

## 6. 数据流

```text
用户页面配置采集规则
  -> 导出或同步到插件配置
  -> 插件在本机定时任务触发
  -> 采集飞书工作协同信号
  -> 应用群聊/关键字/时间窗口过滤
  -> 生成统计聚合和日报草稿
  -> 写入本地报告与 raw-chat 明细
  -> 回传平台服务端
  -> 后端进入 ES / 关系库 / AI 总结链路
```

## 7. 定时策略

默认定时：

- 每天 `17:30` 运行一次

说明：

- 适合统计前一天的工作信息。
- 后端可以在当天上午展示“昨日汇总”。
- 结合 AI 模型后可自动生成日报草稿。

后续如果要扩展周报，可以在服务端把 7 天数据做滚动汇总，不需要插件额外增加复杂逻辑。

## 8. 配置分层

### 8.1 本地配置

本地配置保存：

- 当前用户标识
- 插件实例 ID
- 本地缓存目录
- 日志目录
- 上报 token
- 调度时间
- 采集范围的本地副本

### 8.2 通用配置

通用配置建议走 Nacos：

- 平台网关地址
- ES 保留周期
- 限流和重试策略
- 日报模板版本
- AI 编排开关

### 8.3 用户页面配置

用户可以在平台页面维护：

- 包含群聊
- 排除群聊
- 包含关键字
- 排除关键字
- 是否采集会议
- 是否采集文档
- 是否允许内容分析
- 采集窗口与默认调度

说明：

- 当前页面只提供指导，不直接代替用户修改本地 YAML。
- 真实配置最终仍以采集器机器上的 `config/application.yaml` 为准。

## 9. 存储边界

插件本地只保存：

- 最近一次统计结果
- 心跳记录
- 失败重试队列
- 用户配置快照
- 原始聊天消息明细（当前已落地）

不建议在本地长期保存：

- 原始会议全文
- 原始文档全文

平台服务端建议保存：

- 配置
- 授权关系
- 聚合统计
- 日报草稿
- 审计日志
- 短期检索事件

当前 ES 状态：

- **尚未正式写入 ES**
- 当前聊天原始事件仍只落本地 `raw-chat/`
- 后续推荐由服务端接收插件回传后统一入 ES，并设置默认保留策略：
  - 原始事件 15 天
  - 聚合统计 180 天

## 10. 接口边界

插件未来对接的平台接口建议如下：

```text
POST /api/productivity/plugin/heartbeat
POST /api/productivity/plugin/upload/chat-events
POST /api/productivity/plugin/upload/meeting-stats
POST /api/productivity/plugin/upload/document-stats
```

当前本地试点版会把报告写到 `data/<userId>/`，方便先把流程跑通。

## 11. 平台关联建议

当前聊天采集里最稳定的用户标识是飞书 `open_id`。

建议平台用户表至少保留下列字段之一：

- `feishu_open_id`
- `feishu_user_id`

当前插件已输出：

- `participants[].feishuOpenId`
- `events[].senderOpenId`
- `events[].mentionedOpenIds`

后端可通过这些字段回填：

- 平台账号
- 真实姓名
- 工号
- 三方工作台 ID

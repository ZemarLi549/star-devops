# cpo-feishu-collector-plugin 使用说明

## 1. 安装前提

- Linux / macOS / Windows 均可。
- 需要本机安装 Go 1.25+ 用于本地构建客户端，或直接使用已打好的发布包。
- 需要具备读取本地配置文件、写入缓存目录的权限。
- 如果要回传平台服务端，需要网络能访问鑫图平台网关。

## 2. 目录结构

```text
cpo-feishu-collector-plugin/
├─ bin/
├─ config/
├─ data/
├─ logs/
└─ docs/
```

其中：

- `config/application.example.yaml` 是配置样例。
- `data/` 存放本地报告与缓存。
- `logs/` 存放运行日志。

## 3. 首次配置

第一版支持两种配置方式：

1. 直接编辑 `config/application.yaml`
2. 通过环境变量覆盖配置项

建议先从样例复制一份：

```bash
cp config/application.example.yaml config/application.yaml
```

### 3.1 重点配置项

- `plugin.user-id`
  - 当前试点用户，默认 `E0028517`
- `plugin.instance-id`
  - 插件实例标识
- `plugin.upload-token`
  - 回传平台时使用
- `plugin.cache-dir`
  - 本地输出目录
- `plugin.log-dir`
  - 日志目录
- `platform.gateway-base-url`
  - 平台网关地址
- `collector.heartbeat-seconds`
  - 心跳频率
- `collector.timezone`
  - 时间窗口时区
- `feishu.app-id`
  - 当前用户自己的飞书应用 App ID
- `feishu.app-secret`
  - 当前用户自己的飞书应用 App Secret
- `feishu.auth-base-url`
  - 飞书认证域名，默认 `https://accounts.feishu.cn`，后续切公司内网定制域名时改这里
- `feishu.open-base-url`
  - 飞书 OpenAPI 域名，默认 `https://open.feishu.cn/open-apis`
- `feishu.redirect-uri`
  - 授权完成后回跳到本机采集器的地址
- `feishu.auth-scopes`
  - 当前采集链路需要申请的用户授权权限列表
- `feishu.user-token-file`
  - 当前用户自己的飞书授权 token 存放路径
- `filters.include-group-regexes`
  - 群聊名称正则白名单
- `filters.exclude-group-regexes`
  - 群聊名称正则黑名单
- `filters.include-group-names`
  - 群聊名称白名单集合
- `filters.exclude-group-names`
  - 群聊名称黑名单集合
- `filters.exclude-bot-interactions`
  - 默认 `true`，统一排除机器人、工作流、审批流和应用通知交互

### 3.2 飞书应用后台必须一次性开通的权限

当前这条“用户 OAuth 授权 + 用户身份读取聊天”的采集链路，建议你在飞书开发者后台一次性开通下面这些权限：

| 权限名 | 作用 | 当前是否必须 |
| --- | --- | --- |
| `offline_access` | 获取 `refresh_token`，支持采集器自动刷新 token | 必须 |
| `im:chat:readonly` | 读取当前用户可见会话列表 | 必须 |
| `im:message:readonly` | 读取消息基础内容 | 必须 |
| `im:message.p2p_msg:get_as_user` | 以用户身份读取单聊消息 | 必须 |
| `im:message.group_msg:get_as_user` | 以用户身份读取群聊消息 | 必须 |

说明：

- 当前版本没有依赖 webhook，也没有依赖事件订阅回调。
- 当前版本不需要统一公共机器人，不需要替所有用户共用一个 app。
- 当前版本先做“主动拉取聊天数据”，会议和文档后续独立接入。

### 3.3 飞书应用后台必须配置的安全项

除了权限，还要在飞书开发者后台补齐下面这些配置：

1. `开发配置 -> 安全设置 -> 重定向 URL`
   当前本地试点必须包含：
   `http://127.0.0.1:17891/callback`
2. 打开“刷新 `user_access_token`”开关
3. 配置完成后发布应用

补充说明：

- 如果以后改成公司内网域名回调，`redirect-uri` 和后台白名单要一起改。
- 如果以后切长连接模式接机器人事件，那是另一条链路，不替代当前 OAuth 授权采集。

### 3.4 用户配置页

平台页面当前只提供指导，不直接保存采集器本地配置。真实配置仍由用户自己维护在：

```bash
config/application.yaml
```

默认口径说明：

- 机器人、工作流、审批流、应用通知交互默认不计入个人工作统计。
- 通用闲聊关键词默认会被过滤，比如午饭、奶茶、摸鱼、周末等。
- 群聊支持 ID、名称和正则三种过滤方式叠加。
- 普通用户下载页默认不展示公共机器人密钥、公共飞书 App Secret、上传 token。

## 4. 启动方式

### 4.1 构建客户端

```bash
bash bin/build.sh
```

### 4.2 前台演示采集

```bash
bash bin/authorize.sh E0028517
bash bin/collect-e0028517.sh
```

作用：

- 先引导当前用户使用自己的飞书应用完成授权
- 再生成一次真实聊天采集报告
- 写入 `data/E0028517/latest-report.json`
- 写入 `data/E0028517/latest-report.md`

### 4.3 后台定时采集

```bash
bash bin/start.sh
```

默认行为：

- 启动守护进程
- 按每天 `17:30` 触发采集，统计窗口默认最近 `1` 天
- 每次采集后更新本地报告

### 4.4 启停脚本

```bash
bash bin/quick-deploy.sh E0028517
bash bin/authorize.sh E0028517
bash bin/start.sh
bash bin/stop.sh
```

脚本会：

- 自动补齐本地 `config/application.yaml`
- 给出授权命令
- 在授权完成后再启动后台采集
- 记录 PID
- 将日志写入 `logs/collector.out`

## 5. 授权说明

当前设计是：

- 每个用户必须使用自己的飞书应用完成授权
- 采集器只保存当前用户自己的 token
- 不使用统一公共机器人采集所有人的聊天数据

执行授权：

```bash
bash bin/authorize.sh E0028517
```

如果只想先看授权链接，不立即启动本地回调：

```bash
FEISHU_APP_ID=cli_xxx FEISHU_APP_SECRET=xxx \
PLUGIN_USER_ID=E0028517 \
./dist/current/cpo-feishu-collector-plugin --print-auth-url
```

### 5.1 自动刷新 token 说明

首次授权成功后，采集器会把 `user_access_token` 和 `refresh_token` 保存到本地。

后续正常情况：

- 采集器会在 `access_token` 快过期前自动刷新
- 刷新后会自动覆盖保存新的 `refresh_token`
- 日常定时采集不需要人工每天重新授权

仍需要人工重新授权的场景：

- 新增了新的飞书授权范围，例如第一次漏开了 `im:chat:readonly`
- `refresh_token` 已过期
- `refresh_token` 被撤销或失效
- 应用后台没有开 `offline_access`
- 应用后台没有开“刷新 `user_access_token`”开关
- 飞书重授权窗口到期，需要重新确认授权

## 6. 试点用户 E0028517

要先跑试点用户，可以直接执行：

```bash
bash bin/authorize.sh E0028517
bash bin/collect-e0028517.sh
```

该命令会输出一份当前用户的聊天统计报告，方便先看结果格式。

## 7. 输出文件

采集后会生成：

- `data/E0028517/latest-report.json`
- `data/E0028517/latest-report.md`
- `data/E0028517/heartbeat.json`

这些文件可作为后续平台接入的本地回放数据。

当前目录也已经规范为：

- `data/E0028517/raw-chat/`
- `data/E0028517/reports/daily/history/`
- `data/E0028517/reports/meeting/history/`
- `data/E0028517/reports/document/history/`
- `data/E0028517/archive/`

其中 `raw-chat/` 目录会用于保存真实采集的聊天原始记录，仍会遵守“默认排除机器人交互”的统计口径。

默认保留策略：

- 聊天原始明细：15 天
- 日报、会议、文档等聚合历史：180 天

## 8. 定时 17:30 说明

插件默认每天在 `17:30` 运行一次，默认统计最近 `1` 天的聊天数据。

如果你要修改时间，可以：

- 在本地配置里改 `collector.schedule-at`
- 或通过环境变量 `PLUGIN_SCHEDULE_AT=07:00`

## 9. 回传服务端

如果已经有平台网关地址和上报 token，可以配置：

- `platform.gateway-base-url`
- `plugin.upload-token`

然后由插件把统计结果回传到后端。

目前第一版先保证：

- 用户自己的飞书应用授权正常
- 工作相关聊天过滤正常
- 本地报告生成正常
- 定时任务正常
- 后续接口预留完整

## 10. 常见问题

### 10.1 启动后没有数据

先检查：

- `data/` 目录是否可写
- `config/application.yaml` 是否存在
- `PLUGIN_USER_ID` 是否设置为 `E0028517`
- 是否已经执行过 `bash bin/authorize.sh E0028517`
- `FEISHU_APP_ID / FEISHU_APP_SECRET` 是否是当前用户自己的飞书应用
- 飞书应用后台是否已经申请并发布以下权限：
  - `offline_access`
  - `im:chat:readonly`
  - `im:message:readonly`
  - `im:message.p2p_msg:get_as_user`
  - `im:message.group_msg:get_as_user`
- 如果这次新增了权限，是否已经重新授权一次

### 10.2 想立刻看结果

直接执行：

```bash
bash bin/authorize.sh E0028517
bash bin/collect-e0028517.sh
```

### 10.3 想停止后台任务

```bash
bash bin/stop.sh
```

### 10.4 想换成别的用户

把 `PLUGIN_USER_ID` 改成对应用户即可。

### 10.5 想加群聊正则过滤

在配置文件中维护：

```yaml
filters:
  include-group-regexes:
    - ".*项目群.*"
  exclude-group-regexes:
    - "(?i).*闲聊.*"
    - "(?i).*机器人.*"
```

### 10.6 想清理飞书聊天、日报、会议等历史记录

```bash
bash bin/clean-history.sh --user E0028517
```

如果想先看会删什么，不真正删除：

```bash
bash bin/clean-history.sh --user E0028517 --dry-run
```
